## Проект: Классификация фейковых новостей с использованием рекуррентных нейронных сетей (RNN, LSTM, GRU)
**Fake News Classification using RNN, LSTM, and GRU**

---

## Описание проекта

### Цель проекта
- Разработать модель для бинарной классификации новостных статей на реальные (`real`) и фейковые (`fake`).
- Сравнить три архитектуры рекуррентных нейронных сетей: **RNN**, **LSTM**, **GRU**.
- Оценить качество моделей по метрикам **Accuracy**, **F1-Score** (для класса "фейк"), **ROC-AUC**, а также по времени обучения.
- Выявить архитектуру, наилучшим образом справляющуюся с задачей при дисбалансе классов.

### Данные
- Использован датасет **FakeNewsNet** с платформы Kaggle (23 196 записей).
- Исходные признаки:
  - `title` – заголовок статьи,
  - `news_url` – URL статьи,
  - `source_domain` – домен источника,
  - `real` – целевая переменная (1 – реальная новость, 0 – фейковая).
- После очистки (удаление дубликатов, пропусков) осталось **21 665 записей**.
- Классы несбалансированы:
  - Реальные новости: **16 554 (76.4%)**
  - Фейковые новости: **5 111 (23.6%)**

---

## Этапы работы

### 1. Загрузка и первичный анализ
- Импорт библиотек: `pandas`, `numpy`, `matplotlib`, `torch`, `torchtext`, `gensim`, `sklearn`, `spaCy`.
- Проверка наличия дубликатов (обнаружено 1204 полные дублирующиеся строки, удалены).
- Обработка пропусков: 327 записей (1.49%) с отсутствующими `news_url` и `source_domain` – удалены.
- Переопределение целевой переменной: создан столбец `fake` как инверсия `real` (1 – фейк, 0 – реальная новость) для удобства интерпретации.

### 2. Инженерия признаков
- Анализ доменов: выявлены источники с высокой долей фейковых новостей (например, `hollywoodlife.com` – 86.6% фейков, `radaronline.com` – 90.3%).
- Создание текстового поля `text` путём конкатенации:
  - `source_domain`
  - разделитель `[SEP]`
  - `title`
  - индикатор подозрительного URL: `[FAKE_URL]` или `[CLEAN_URL]` (на основе наличия в URL ключевых слов, связанных с фейками).
- Это позволило модели учитывать как содержание заголовка, так и авторитетность источника.

### 3. Предобработка текста и подготовка данных для PyTorch
- Использование `torchtext` для создания полей `Field` и `LabelField`.
- Токенизация с помощью библиотеки **spaCy** (модель `en_core_web_sm`).
- Построение словаря по тренировочным данным – размер словаря **18 320 токенов**.
- Создание датасета `torchtext.data.Dataset` из примеров.
- Разделение на train/test в соотношении **80/20** (17 332 / 4 333).
- Создание итераторов `BucketIterator` для эффективной подачи данных (batch size = 30, сортировка по длине текста).

### 4. Построение Word2Vec эмбеддингов
- Извлечение токенизированных текстов из тренировочного датасета.
- Обучение модели **Word2Vec** (размерность 100, окно 5, min_count=1, skip-gram) на этих текстах.
- Построение матрицы эмбеддингов размером `[vocab_size, 100]`:
  - для слов, присутствующих в Word2Vec, используются обученные векторы;
  - для неизвестных слов (`<unk>`, `<pad>`) – случайная инициализация с нормальным распределением.
- Загрузка матрицы в слой `nn.Embedding` (параметр `freeze=False` для дообучения).

### 5. Определение архитектур RNN

Были реализованы три класса моделей, наследующие `nn.Module`:

- **RNNModel**: однослойная элмановская RNN.
- **LSTMModel**: однослойная LSTM.
- **GRUModel**: однослойная GRU.

**Общие параметры:**
- Размер эмбеддинга: 100
- Размер скрытого состояния: 64
- Количество слоёв: 1
- Dropout: 0.6
- Выходной слой: линейный (64 → 1) с последующей сигмоидой через `BCEWithLogitsLoss`

### 6. Обучение моделей
- **Функция потерь**: `BCEWithLogitsLoss` (без взвешивания классов, хотя веса были рассчитаны).
- **Оптимизатор**: AdamW (lr = 0.0001, weight_decay = 0.5).
- **Планировщик learning rate**: ручное уменьшение в два раза при отсутствии улучшения валидационной точности в течение 3 эпох.
- **Early Stopping**: остановка, если валидационная точность не улучшается 5 эпох подряд.
- Максимальное число эпох: 30.
- Каждая модель обучалась отдельно, сохранялись веса лучшей модели (по валидационной точности).

### 7. Оценка и сравнение
- Для каждой модели вычислены:
  - точность (accuracy),
  - F1-мера для класса "фейк",
  - ROC-AUC,
  - время обучения.
- Построены графики loss/accuracy для тренировки и валидации, а также ROC-кривые на тестовой выборке.
- Результаты сведены в итоговую таблицу.

## Результаты сравнения моделей

| Модель | Accuracy (%) | F1-Score (fake) | ROC-AUC | Время обучения (сек) |
|--------|--------------|------------------|---------|----------------------|
| **LSTM** | **87.68**    | **0.6920**       | **0.8985** | 55.40                |
| GRU      | 86.89        | 0.6667           | 0.8908    | 65.51                |
| RNN      | 86.25        | 0.6303           | 0.8794    | 45.29                |

- **LSTM** показала наилучшие результаты по всем трём ключевым метрикам (Accuracy, F1, ROC-AUC), подтверждая свою способность лучше моделировать долгосрочные зависимости в тексте.
- **GRU** немного уступила LSTM, но превзошла обычную RNN.
- **RNN** обучилась быстрее всех, но качество классификации фейков оказалось самым низким (F1 = 0.63).

## Выводы

1. **LSTM является оптимальным выбором** для задачи классификации фейковых новостей на данном наборе данных: она даёт наилучший баланс между точностью и полнотой для целевого класса.
2. **Проблема дисбаланса классов сохраняется**: все модели демонстрируют высокий accuracy (>86%), но существенно более низкий recall для фейковых новостей (50–59%). Это означает, что около 40% фейков остаются нераспознанными.
3. **GRU предлагает компромисс**: качество лишь немного ниже, чем у LSTM, но время обучения на 18% больше.
4. **RNN уступает в качестве**, но является самой быстрой; может использоваться при жёстких ограничениях на время обучения.
5. **Добавление признака `[FAKE_URL]` и учёт домена** положительно повлияли на способность модели различать источники.
6. **Дальнейшие улучшения** могут включать:
    - Применение техник борьбы с дисбалансом (взвешенная функция потерь, oversampling, focal loss).
    - Использование предобученных эмбеддингов (GloVe, fastText) вместо Word2Vec.
    - Тонкая настройка гиперпараметров (размерность скрытого слоя, количество слоёв, dropout).
    - Ансамблирование моделей.
